# Finite-Structure Validation Runbook

Step-by-step instructions for processing each example structure end-to-end.

The pipeline has two halves:

1. **Cluster** (heavy DFT, hours to days): `phonon_inputs pipeline` produces
   `fc3.hdf5` from a YAML config. Done once per system.
2. **Local** (minutes): `python -m phonon_inputs.finite_analysis` reads that
   `fc3.hdf5` and produces a uniform validation report (sparsity, decomposition,
   ASR, SSE, cutoff sensitivity).

The Python entry point is always run from `phonon/`.

## Available structures

| System              | Config file                          | Notes                                  | DFT cost      |
|---------------------|--------------------------------------|----------------------------------------|---------------|
| Si primitive (FCC)  | `configs/si_primitive/prim_vasp.yaml`        | 2-atom prim → 3³ supercell (54 atoms)  | small         |
| Si primitive (DFPT) | `configs/si_primitive/dfpt.yaml`             | D3Q route, same crystal                | small         |
| Si primitive large k| `configs/si_primitive/prim_largek.yaml`      | Convergence variant                    | small         |
| SiNW(100) (existing)| `configs/sinw/sinw100_d5a_vasp.yaml`             | 53-atom unit cell, 1×1×2 SC by default | medium        |
| SiNW(100) d=6 Å     | `configs/sinw/sinw100_d6a_vasp.yaml`*        | Larger wire, generated by setup script | medium-large  |
| SiNW(100) d=9 Å     | `configs/sinw/sinw100_d9a_vasp.yaml`*        | Largest wire variant                   | large         |
| GeNW(100)           | `configs/genw/genw100_d6a_vasp.yaml`*        | Same geometry, Si→Ge                   | medium        |
| SiGeNW(100)         | `configs/sigenw/sigenw100_fge50_vasp.yaml`*  | 50/50 alloy variant                    | medium        |

## 0. One-time scaffolding

Generate the new YAML configs (these scripts only write YAML; no DFT yet):

```bash
cd phonon/

# SiNW family
python examples/setup_sinw100.py --diameter 6.0  # → configs/sinw/sinw100_d6a_vasp.yaml
python examples/setup_sinw100.py --diameter 9.0  # → configs/sinw/sinw100_d9a_vasp.yaml

# Ge / SiGe wire
python examples/setup_genw100.py --diameter 6.0  # → configs/genw/genw100_d6a_vasp.yaml
python examples/setup_sige_nw.py --frac-ge 0.5   # → configs/sigenw/sigenw100_fge50_vasp.yaml

# Finite CNT segment
python examples/setup_cnt_finite.py --n-cells 4  # → configs/cnt/cnt33_finite_n4_vasp.yaml

# Si chain (also the unit-test fixture)
python examples/setup_si_chain.py --n-atoms 8    # → configs/chain/si_chain_n8_auto.yaml
```

Inspect the generated YAML for sane lattice/positions before queuing DFT.

## 1. Cluster workflow (per system)

Four CLI commands; each writes to the work_dir specified in the YAML
(`relax.work_dir`, `thirdorder.work_dir`, `hiphive.work_dir`).

```bash
# Step 1: relax (vc-relax for periodic, relax for finite/wire)
python -m phonon_inputs pipeline --config <config>.yaml

# OR, broken into sow/run/reap stages for cluster-friendly batching:
python -m phonon_inputs fc3-sow   --config <config>.yaml   # generate displacements
sbatch run_qe.sh                                            # run DFT externally
python -m phonon_inputs fc3-reap  --config <config>.yaml   # collect forces → fc3.hdf5
```

At the end you have one (or more) `<work_dir>/fc3.hdf5` files. The
hiphive route also produces `hiphive_meta.json` next to the FC HDF5,
which the analysis loader reads for the actual supercell size.

Verify the reap landed correctly:

```bash
python -c "import h5py; f=h5py.File('<work_dir>/fc3.hdf5'); \
           print(f['fc2'].shape, f['fc3'].shape)"
```

## 2. Local validation pipeline (per system)

Drive the analysis pipeline with the matching YAML:

```bash
cd phonon/

python -m finite_analysis \
    --config configs/chain/si_chain.yaml \
    --out-dir finite_analysis_out/si_chain \
    --analyses all \
    --rank-sweep 2,4,8,16,32 \
    --n-freq-pos 64 \
    --temperature 300 \
    --skip-quatrex-run     # drop this flag once Task 9 lands
```

Common variations:

```bash
# Fast sanity slice (under a minute on the SiNW)
--analyses fc_quality,physical

# Full report
--analyses all

# Override the reaped fc3.hdf5 (useful when comparing variants)
--fc3-path reaps/hiphive_sinw100_vasp_larger/fc3.hdf5
```

## 3. What to look at, in order

Open `<out-dir>/summary.json` first — it contains the headline numbers
for every analysis. Then the per-analysis subdirs:

### `fc_quality/`
Single merged directory: FC2/FC3 quality + dispersion + sparsity (the
legacy ``sparsity/`` analysis was folded in here).
- `fc_quality.json` — FC2/FC3 magnitudes, high-symmetry q frequencies,
  nnz-at-1e-3 summary.
- `fc_quality_fc2_distance.png`, `_fc3_distance.png` — log-y plots of
  mean Frobenius vs interatomic distance / triplet diameter; the FC3
  plot draws the hiphive cutoff as a dashed vertical line.
  **What to check:** monotonic decay; FC2 should reach ~0 at the
  hiphive `cutoffs[0]`; FC3 should reach ~0 at `cutoffs[1]`.
- `fc_quality_dispersion.png` — Γ→Z bands. **What to check:** real
  acoustic modes, no spurious negative branches except at Γ.
- `sparsity_fc2_heatmap.png` — atomic-block Frobenius matrix (z-sorted).
  Banded structure ⇒ short-range FC. Non-zero upper-left / lower-right
  corner blocks signal PBC wraparound (FC2 cutoff close to L/2).
- `sparsity_fc3_decay_1d.png` — same data as `fc_quality_fc3_distance`
  with a different binning; cross-check.
- `sparsity_fc3_scatter_3d.png` — 3D scatter + 2D `max_k` projection.
  **What to check:** support concentrated near the diagonal i ≈ j ≈ k.
- `sparsity_nnz_table.csv` — fraction of nonzeros vs threshold.

### `decomposition/`
- `decomp_rank_sweep.csv` — six methods × multiple ranks. Columns: `n_params`,
  `frob_err`, `nnz_at_1em3`, `nnz_at_1em4`. **What to check:**
  - Which method reaches `frob_err < 0.05` at lowest `n_params`?
  - Does any method's `nnz_at_1em3` go *below* the dense baseline (in
    `summary.json → decomposition.baseline.nnz_at_1em3`)?
- `decomp_frob_vs_params.png` — log-log of error vs cost. INDSCAL / CP
  typically dominate at low rank.
- `decomp_nnz_vs_eps.png` — reconstruction nnz vs `n_params`, with
  the dense-FC3 baseline as a horizontal line. **Headline:** does
  decomposition genuinely save nonzeros?

### `physical/`
- `physical.json`:
  - `fc2_hermiticity.rel_frob` — should be ≪ 1 (typically 0 by
    construction).
  - `fc2_asr.rel_frob` — should be ≤ 10⁻¹⁰ if symfc / phonopy was
    used; hiphive may leave a small residual.
  - `fc3_perm_sym` — every entry should be 0 (the lifted FC3 is
    S3-symmetric by construction in `build_fc3_target`).
  - `fc3_asr_legs.leg_j` and `.leg_k` — relative to `.norm`. **Red
    flag:** ratio > 0.05 means the FC3 fit broke ASR; symptoms include
    spurious low-frequency SSE features.
  - `dispersion.n_negative_modes` — should be 0 or a handful. Many
    negative modes ⇒ FC2 indefinite.

### `sse_sparsity/`
- `sse_sigma_block_frob_synth.csv` — per-(I, J) Σ^< Frobenius norm from
  the synthetic GF. **What to check:** decay with |I − J|; for a
  truly NN-tridiagonal Σ pattern only |I−J| ≤ 1 entries should be
  large.
- `sse_sigma_heatmap_synth.png` — same data as a heatmap.
- `sse_sigma_block_frob_quatrex.csv`, `sse_sigma_heatmap_quatrex.png` — only
  if `--skip-quatrex-run` was *not* passed and Task 9 is implemented.

### `cutoffs/`
- `cutoffs_sweep.csv` — mean and max relative Frobenius diff vs the
  `baseline` config, per cutoff knob.
- `cutoffs_sigma_frob_vs_cutoff.png` — bar chart on log axis. **Headline:**
  at what magnitude threshold does the SSE start to drift by > 1%?
  Below that threshold you can prune FC3 with no transport penalty.

## 4. Recommended testing order

For a *new* structure, run in this order to catch problems early:

1. `--analyses physical` first (~seconds). If ASR or dispersion is
   broken, the rest of the analyses are meaningless.
2. `--analyses fc_quality` (~minute). Confirms the FC has
   the expected decay and locality.
3. `--analyses decomposition` (~minutes). PCP is off by default;
   pass `--include-pcp` if you specifically want to audit it.
4. `--analyses sse_sparsity,cutoffs` (~minutes for small systems,
   tens of minutes for SiNW-scale). The bubble is O(N⁴) per block,
   so wire-scale systems need a coarse `--n-freq-pos`.

Then promote the figures to `document/src/fig/finite_analysis/<system>/`
and let LaTeX pick them up via the existing `\includegraphics` lines
in `document/src/results.tex § Finite-Structure Validation`.

## 5. Continuous-validation snippet

For a one-shot regression after any FC change:

```bash
cd phonon/
for cfg in configs/si_primitive/prim_vasp.yaml configs/sinw/sinw100_d5a_vasp.yaml; do
    name=$(basename "$cfg" .yaml)
    python -m finite_analysis \
        --config "$cfg" \
        --out-dir "finite_analysis_out/$name" \
        --analyses fc_quality,physical,decomposition \
        --rank-sweep 2,4,8,16 \
        || { echo "FAIL: $cfg"; exit 1; }
done
```

Wire this into CI once the suite is stable (pre-commit / pre-merge),
gated on the existing reap directories being available.
